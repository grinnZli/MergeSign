# Архитектура MergeSign

## Цель проекта

MergeSign — оконное приложение для Windows (WPF, C#), которое объединяет
несколько отсоединённых электронных подписей (detached signature, файлы
`.sig`) для одного и того же исходного документа в один файл подписи.

Типовой сценарий: несколько подписантов подписывают один документ отдельно,
после чего подписи объединяются в единый `.sig` для загрузки на портал
госоргана или в информационную систему.

Дополнительные возможности:

- проверка привязки подписи к исходному PDF-документу;
- извлечение вложенного содержимого из присоединённой подписи (`.p7s`/`.sig`);
- разделение файла с несколькими подписями на отдельные `.sig`.

## Ключевые ограничения

- **Тип приложения — оконное (WPF).** Весь вывод выполняется в интерфейс,
  консольный режим не предусмотрен.
- **Используется локально установленный КриптоПро CSP** через Windows
  CryptoAPI (`crypt32.dll`, `advapi32.dll`) посредством P/Invoke из C#.
- **Не используются КриптоАРМ Server и sign.kloud.one API.**
- **CMS/ASN.1 не реализуется с нуля** — работа идёт через функции
  `CryptMsg*` установленного провайдера.
- **Целевая платформа — Windows 10/11 x64**, так как необходимы системные
  криптографические библиотеки и зарегистрированный провайдер КриптоПро.
- **Язык реализации — C# (.NET 8) + WPF.**
- Системный реестр и настройки КриптоПро не изменяются.
- Вызовы CryptoAPI выполняются в фоновом потоке (`Task.Run`), UI обновляется
  через `Dispatcher`; UI-поток не блокируется.

## Техническая суть объединения подписей

Объединение — это не конкатенация файлов, а слияние нескольких структур
CMS SignedData в одну: коллекции `SignerInfo` и сертификаты подписантов
собираются в единый контейнер.

### Основной подход (Windows CryptoAPI / КриптоПро CSP)

1. Первый выбранный `.sig` используется как базовое CMS-сообщение.
2. Для каждого следующего `.sig`:
   - `CryptMsgOpenToDecode` + `CryptMsgUpdate` — загрузить подпись;
   - `CryptMsgGetParam(CMSG_CMS_SIGNER_INFO_PARAM)` — извлечь `SignerInfo`;
   - `CryptMsgGetParam(CMSG_CERT_PARAM)` — извлечь сертификат подписанта.
3. Добавить извлечённые данные в базовое сообщение:
   - `CryptMsgControl(CMSG_CTRL_ADD_CMS_SIGNER_INFO)` — добавить подпись;
   - `CryptMsgControl(CMSG_CTRL_ADD_CERT)` — добавить сертификат.
4. `CryptMsgGetParam(CMSG_ENCODED_MESSAGE)` — получить итоговый BLOB.
5. Записать результат в выходной `.sig`.

### Чего не делать

- **Не использовать `CMSG_CTRL_ADD_SIGNER`** — эта функция создаёт новую
  подпись и требует согласованности алгоритмов, что ломается на смешанных
  подписях. Для добавления уже существующих подписей нужен именно
  `CMSG_CTRL_ADD_CMS_SIGNER_INFO`.

### Проверка привязки к документу

Для проверки привязки вычисляется хеш исходного документа и сравнивается с
`messageDigest` из подписанных атрибутов (OID `1.2.840.113549.1.9.4`),
извлекаемым через `SignedCms`. Для ГОСТ-алгоритмов хеш документа
вычисляется средствами КриптоПро CSP.

### Разделение и извлечение подписей

`SplitSignatures` для каждой подписи заново открывает исходный файл, находит
сертификат именно этой подписи через `CMSG_SIGNER_CERT_INFO_PARAM`,
удаляет остальные подписи и сертификаты (`CMSG_CTRL_DEL_SIGNER`,
`CMSG_CTRL_DEL_CERT`) и кодирует результат через `CMSG_ENCODED_MESSAGE`.
`ExtractEmbeddedContent` открывает присоединённое сообщение без флага
`CMSG_DETACHED_FLAG` и читает вложенное содержимое через
`CMSG_CONTENT_PARAM`.

## Архитектура приложения

- **Тип приложения:** оконное WPF-приложение.
- **UI:** WPF (`MainWindow.xaml`) — список подписей, выбор PDF, проверка
  привязки, объединение, извлечение и разделение подписей, строка статуса,
  выдвижная панель с подробностями сертификата.
- **Ядро:** отдельная библиотека классов `MergeSign.Core` с P/Invoke к
  `crypt32.dll` и `advapi32.dll`.
- **Потокобезопасность:** вызовы CryptoAPI выполняются в `Task.Run`, UI
  обновляется через `Dispatcher`.

```
MergeSign/
├── MergeSign.sln
├── MergeSign.Gui/                 # WPF-проект (.NET 8)
│   ├── App.xaml
│   ├── App.xaml.cs
│   ├── MainWindow.xaml            # Интерфейс приложения
│   ├── MainWindow.xaml.cs         # Обработчики команд и обновление UI
│   ├── SignerViewModel.cs         # Модель представления подписи

└── MergeSign.Core/                # Библиотека классов
    ├── NativeMethods.cs           # P/Invoke-объявления и константы CryptoAPI

    ├── ErrorHelper.cs             # Форматирование ошибок Win32/CryptoAPI
    ├── Models.cs                  # DTO: данные подписи и сертификата
    └── MergeSign.Core.csproj
```

### Компоненты

- **`CmsMerger`** — вся работа с CMS: чтение `.sig`, подсчёт и извлечение
  подписей и сертификатов, объединение, проверка привязки, разделение и
  извлечение вложенного содержимого.
- **`NativeMethods`** — объявления `CryptMsg*`, функций работы с
  сертификатами (`CertCreateCertificateContext`,
  `CertFreeCertificateContext`), хешированием (`CryptCreateHash`,
  `CryptHashData`, `CryptGetHashParam`) и параметрами провайдера
  (`CryptGetProvParam`).
- **`ErrorHelper`** — человекочитаемые сообщения об ошибках Win32 с кодом.
- **`Models`** — `SignerData` и `CertificateInfo`.
- **GUI** — накапливает подписи в списке, проверяет наличие КриптоПро при
  запуске, показывает сведения о сертификате и статус привязки, предлагает
  имя выходного файла на основе имени PDF.

### Особенности реализации

- При добавлении подписей дубликаты определяются по отпечатку сертификата
  (`Thumbprint`) и пропускаются.
- Для ГОСТ-хеширования используется провайдер
  `Crypto-Pro GOST R 34.10-2012 Cryptographic Service Provider`.
- В строке состояния отображаются имя и версия установленного
  криптопровайдера; при его отсутствии операции блокируются.
- Публикация возможна одним автономным `.exe` (self-contained,
  `PublishSingleFile`).
